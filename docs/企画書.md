# lsir-cs システム 企画書

**作成日**: 2026-07-30  
**対象**: LIST Sotheby's International Realty チーム  
**バージョン**: 1.0

---

## 1. 背景・課題

LIST Sotheby's International Realty のチームでは、日常業務における情報管理が複数のツール（メール・Slack・Excel・手書きメモ）に分散しており、以下の課題が生じていた。

- **タスク漏れ・抜け**: 担当者への依頼や締切情報がメールやSlackに埋もれ、フォローアップが属人化
- **進捗の可視化不足**: チームリーダーが誰が何をいつまでに行うかをリアルタイムで把握できない
- **バイヤー情報の分散**: バイヤーリストがGoogle SheetsとExcelに点在し、更新反映が遅延
- **顧客情報の分散**: ZOHO・Appfolio・WPなど複数システムに顧客データが断片化
- **Slack通知の一方通行**: ハワイ拠点との連絡がチャットのみで記録性が低い

---

## 2. 目的・目標

### 主目的

**チームの業務情報を一元化し、担当者・期限・進捗を可視化することで業務効率を向上させる。**

### 数値目標（定性・定量）

| 目標 | 現状 | 目指す姿 |
|---|---|---|
| タスクの抜け漏れ | メール・Slackで散在 | 全タスクをシステムで管理し漏れゼロ |
| 進捗確認コスト | 口頭確認・Slack往復 | ダッシュボードで即時確認 |
| バイヤーリスト更新 | 複数ファイルに重複保存 | Google Sheets をシングルソースに |
| 顧客情報参照 | 複数システムを横断検索 | lsir-cs 1箇所で参照・更新 |

## 3. システム概要

**システム名**: lsir-cs（LIST Sotheby's International Realty Customer & Task System）

**利用形態**: Webアプリケーション（ブラウザからアクセス。スマートフォン対応）

**アクセス方式**: Googleアカウント / Microsoft AzureAD によるSSOログイン。ホワイトリスト制でチームメンバーのみ利用可能。

**主要機能サマリー**:

| カテゴリ | 機能 |
|---|---|
| タスク管理 | 作成・編集・担当者割当・期限管理・サブタスク・添付ファイル・コメント |
| タスク可視化 | カンバン・リスト・ギャラリー・カレンダー・タイムライン（5種ビュー） |
| バイヤーリスト | Google Sheets 連携・プロジェクト別スプレッドシート対応 |
| 顧客管理（CRM） | 顧客情報一元管理・タスクとの紐づけ・ZOHO反映依頼通知 |
| プロジェクト管理 | プロジェクト台帳（スプレッドシートIDと紐づけ） |
| 通知・自動化 | Slack通知・Slackコマンドからのタスク作成・AI タスク自動生成 |

## 4. ユーザー・利用シナリオ

### 利用者

| ロール | 利用内容 |
|---|---|
| チームスタッフ | タスクの確認・ステータス更新・コメント・バイヤー情報参照 |
| マネージャー | タスク作成・担当者割当・進捗ダッシュボード確認・カレンダービュー |
| システム管理者 | ホワイトリスト管理・カテゴリ設定・自動化ルール設定 |

### 主な利用シナリオ

**① PM（プロパティマネジメント）案件管理**  
ハワイからのメールをAI解析でタスク化 → 担当者が翻訳・オーナー回答・ハワイへの返信を4ステップのサブタスクで管理。ステータスは専用フロー（WaitingEstimate → WaitingOwnerApproval → WaitingCompletionReport → Done）で遷移。

**② 日常タスク管理**  
Slackからのメンション・メールをタスクとして登録。カンバンビューで進捗を視覚的に確認。期限超過タスクはダッシュボードでアラート表示。

**③ バイヤー対応**  
プロジェクト別バイヤーリストをGoogle Sheetsと同期しながら参照・更新。サブタスクにバイヤーへのリンクを貼り、タスクと顧客情報を紐づけ。

**④ 顧客情報管理**  
新規リードをlsir-csに登録 → 変更時にDX担当へSlack通知 → ZOHO手動反映。次回フォローアップ日を設定して期限管理。

## 5. システム構成・技術方針

### アーキテクチャ

```
ブラウザ（React SPA）
  ↕ HTTPS
Azure Static Web Apps
  ├─ /app  ← フロントエンド（Vite ビルド）
  └─ /api  ← Azure Functions（Node.js 20 / サーバーレス）
              ↕
         Azure Cosmos DB（NoSQL）
              ↕
         Azure Blob Storage（添付ファイル）
              ↕
     Google Sheets API / Slack API / n8n（自動化）
```

### 技術選定の理由

| 選定技術 | 採用理由 |
|---|---|
| Azure Static Web Apps | Azure エコシステム内で完結。CI/CDが GitHub Actions と標準統合。SPA + Functions のセット管理が容易 |
| Azure Cosmos DB | スキーマレスでフィールド追加が柔軟。タスクデータのような構造変化に強い |
| React 19 + MUI v7 | 高い開発効率。コンポーネント設計でUIを統一 |
| Tiptap v3 | オープンソースのリッチテキストエディター。HTMLを直接出力。ProseMirrorベースで拡張性が高い |
| n8n | ノーコードで複雑なAI・Slackフローを構築可能。Claude API 連携・定期バッチに活用 |
| Google Sheets | バイヤーリストの既存ワークフローを維持しながらWeb UIを追加 |

## 7. データ保護・セキュリティ方針

| 項目 | 方針 |
|---|---|
| 認証 | Google / Microsoft SSO（パスワード管理なし） |
| アクセス制御 | ホワイトリスト制。登録済みメールアドレスのみログイン可 |
| 通信 | HTTPS（Azure SWA が標準適用） |
| データ保存 | Azure Cosmos DB（Azure のセキュリティポリシー準拠） |
| 添付ファイル | Azure Blob Storage（プライベートコンテナ） |
| 機密情報 | 環境変数（Azure Portal Application Settings）で管理。コードにシークレットを含まない |
